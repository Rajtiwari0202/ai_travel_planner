# Architecture

TravelAgenticAI is organized as a local-first monorepo:

- `backend/app`: canonical FastAPI application, agent orchestration, SQLite persistence, providers, optimization, validation, and API routes.
- `frontend`: Vite React TypeScript client.
- `research`: reproducible benchmark scripts, generated results, figures, and paper draft.
- `docs`: architecture, API, data-source, and demo documentation.

## Core Design Decisions

1. The browser never geocodes itinerary text. Coordinates are returned by the backend.
2. Default providers are curated or deterministic fallback providers and are visibly labeled as estimated, synthetic, fallback, cached, live, or open-data.
3. Agent progress is generated by the backend orchestration flow and persisted as `AgentEvent` records.
4. SQLite is the default persistence layer so the app runs locally without paid infrastructure.
5. Template narrative generation is the default; Ollama is optional and disabled unless configured.
